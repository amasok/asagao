# ADR 0006: ユースケースはローカルへの反映と outbox までを行い、送り方は入り口から Sender で受ける

- 状態: 提案 (Issue #69 の設計の段階)
- 日付: 2026-11-16

## 背景

- 書き込みは、どの入り口でも「ローカルに反映して outbox に積む」(store の `*Local` の 1 つのトランザクション) のあと、送る。
- 送り方は入り口ごとに違う (write-flow の仕様):
  - CLI と MCP は、すぐ `Syncer.Push` を 20 秒の期限で呼び、送れたかを返す。
  - TUI は、同期全体 (`Syncer.Run`) を頼み、同期中なら終わってからもう一度行う。送れたかは画面の未送信の数で示す。
  - 読み取り専用の MCP と、TUI の `--offline` は送らない。
- 入り口ごとの小さな違い (担当の既定、名前の解決、エラーの文字列) は、今の振る舞いで、テストが守っている。

## 決めたこと

1. ユースケース (`internal/app`) は、**入力の解釈 → 名前の解決 → 説明文の変換 → store の `*Local` の呼び出し** までを行う。1 つのユースケースが呼ぶ store の書き込みは、今の入り口が呼んでいるものと同じにする (トランザクションの単位を変えない)。
2. **送り方は `Sender` ポートで受ける。** `type Sender interface { Send(ctx, gid string) WriteResult }` のような形。組み立てで、CLI と MCP には `Push` を呼ぶ実装を、TUI には同期を頼む実装を、送らない形には何もしない実装を渡す。形は段階 a3 (TUI を移すとき) に決める。a1 では送り方を移さない。
3. **入り口ごとの違いは、残す。** ユースケースの引数か、入り口の側に置く。
   - 期日・担当などの入力の誤りは、ユースケースが**欄の名前を持つエラー** (`*app.FieldError{Field, Err}`) で返し、入り口が今と同じ文字列 (`--due: …`、`due_on: …`) に包み直す。
   - TUI の「今見ているプロジェクトのセクション」「プロジェクトの画面では担当を空」は、TUI が gid を決めてユースケースに渡す (名前の解決をしない入力の形を用意する)。
   - 違いをなくすのは、振る舞いの変更なので、別の Issue にする。
4. **ポートの引数と戻り値に、adapter の型を使わない。** 今の store のメソッドが store の型 (`store.NewTask`、`store.TagEdit` など) を使っているときは、その型を先にドメインか共有の型 (`domain/task`、`readmodel`) に移し、store には型の別名を残す。これで `*store.Store` がポートをそのまま満たし、app は store を import しない。a1 では `NewTask`・`TagEdit`・`TagRef` を `domain/task` に移す。
5. ユースケースは時刻を `Clock` で受ける。`time.Now` を直接呼ばない (MCP の `s.Now`、CLI の `now` と同じ扱い)。
6. ユースケースの単体テストは、偽の `TaskStore` (インターフェース) で書く。入り口のテスト (本物の store と httptest の偽の Asana) は変えずに残し、振る舞いが同じことの証拠にする。

## 結果

- 段階 a のあと、入り口は「入力を集める → ユースケースを呼ぶ → 送る (Sender) → 表示する」だけになる。ユースケースは送らない。送るのは入り口で、`sent` と `task_gid` の決め方 (CLI は未送信の数も見て、送れたローカル gid を空にする。MCP は未送信の数を見ず、本物の gid を返す) も入り口に残す。
- `internal/app` は `internal/sync` を import しない。sync を呼ぶのは Sender の実装 (組み立ての側) になる。
- ユースケースの数は、書き込みの種類 (write-flow の仕様の表で 18 ほど) に近くなる。小さなものは 1 つのファイルにまとめる。

## 選ばなかった案

- **ユースケースの中で送る**: CLI・MCP と TUI で送り方が違うので、ユースケースに入り口の事情が入る。読み取り専用の扱いも入る。
- **違いをなくして 1 つにそろえる**: 重複はさらに減るが、振る舞いが変わる。#69 の「移るのはコードの場所と依存の向きだけ」に反する。
