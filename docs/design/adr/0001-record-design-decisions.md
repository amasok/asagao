# ADR 0001: 設計の判断は docs/design/adr に 1 件 1 ファイルで残す

- 状態: 提案 (Issue #69 の設計の段階)
- 日付: 2026-11-16

## 背景

Issue #69 では、構成を何段階かに分けて移す。段階ごとに別の PR になり、作業する人 (人と AI のエージェント) も変わる。「なぜこの形にしたか」が PR の説明やチャットに散らばると、あとの段階で同じ議論をやり直すことになる。

## 決めたこと

- 設計の文書は `docs/design/` に日本語で置く。入口は `docs/design/README.md`。
- 判断は 1 件 1 ファイルで `docs/design/adr/NNNN-<短い英語の名前>.md` に書く。番号は 4 桁の通し番号。
- 書く項目: 状態 (提案 / 採用 / 置き換え済み)、日付、背景、決めたこと、結果、選ばなかった案。
- 一度採用した ADR は書き換えない。判断を変えるときは新しい ADR を足し、古いほうの状態を「置き換え済み (ADR NNNN)」にする。誤字や、リンク切れの修正は書き換えてよい。
- 振る舞い (何をするか) は OpenSpec の仕様 (`openspec/specs/`) に、構成 (どこに置くか、何に依存するか) は ADR に書く。同じことを両方に書かない。

## 結果

- 段階 a〜d の PR は、関係する ADR を説明に書く。ADR と違う形にするときは、先に ADR を足す。
- このブランチの ADR は「提案」。リーダーが取り込むときに「採用」にする。

## 選ばなかった案

- **Issue のコメントに書く**: 検索しにくく、コードと一緒に版を管理できない。
- **1 つの大きな設計書に書く**: どの判断がいつ変わったかが追えない。
