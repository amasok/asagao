# asana-tui 要件定義（v1.0）

> ステータス: 確定（M0 完了）。`[要確認]` の項目は実装時に確認する。

## 1. 背景・目的

- ブラウザ / デスクトップアプリを開かずに、ターミナルから Asana のタスクを素早く確認・操作したい。
- キーボードだけで完結する操作体系により、日々のタスク処理（確認・完了・作成・コメント）の速度を上げる。
- **オフラインでも使える**: ネットワークがなくても閲覧・編集でき、復帰時に同期する。
- **AI フレンドリー**: AI エージェントが同じデータを扱えるよう、JSON を出力する CLI と MCP サーバーを提供する。
- **Asana の無料プラン（Personal）の機能は基本的にすべて使える**ようにする。ただし Asana API が提供していない機能は除く（4.4 参照）。
- 有料プラン限定の機能は対象外。

## 2. 想定ユーザー

- 主に開発者本人（ターミナル中心で作業するエンジニア）。
- Claude Code などの AI エージェント（MCP / CLI 経由）。

## 3. 全体構成

```
                ┌──────────── asana-tui (単一バイナリ) ────────────┐
                │                                                   │
  人間 ───────▶ │  TUI (Bubble Tea)                                 │
  AI / スクリプト▶ │  CLI (`asana-tui task list --json` など)          │
  AI エージェント ▶ │  MCP サーバー (`asana-tui mcp`, stdio)            │
                │        │                                          │
                │        ▼                                          │
                │  Core: ドメインモデル / 操作（全フロントエンド共通） │
                │        │                                          │
                │   ┌────┴─────┐                                     │
                │   ▼          ▼                                     │
                │ Local Store  Sync Engine ──▶ Asana API Client ──▶ Asana
                │ (SQLite)     (取得・送信待ちキュー)  (OAuth 2.0)        │
                └───────────────────────────────────────────────────┘
```

- TUI / CLI / MCP は同じ Core と Local Store を使う。**読み取りは常にローカルストアから**行うので、高速でオフラインでも動く。
- 書き込みはまずローカルに反映し、送信待ちキュー（outbox）に積む。オンライン時に Sync Engine が Asana へ送る。

## 7. AI フレンドリー機能

### 7.1 CLI

```sh
asana-tui task list --assignee me --due-before 2026-11-20 --json
asana-tui task show <gid> --json
asana-tui task create --project <gid> --name "..." --due 2026-11-20
asana-tui task complete <gid>
asana-tui comment add <gid> --text "..."
asana-tui search "キーワード" --json
asana-tui sync            # 手動同期
asana-tui sync status     # 送信待ちキューの確認
```

- 出力は安定したスキーマの JSON。終了コードでエラー種別を区別する。

### 7.2 MCP サーバー

- `asana-tui mcp` で stdio トランスポートの MCP サーバーとして起動。Claude Code などに登録して使う。
- ツール（案）:

| ツール | 種類 | 内容 |
|--------|------|------|
| `list_tasks` | 読み取り | 条件（担当者・プロジェクト・期日・完了状態）でタスク一覧 |
| `get_task` | 読み取り | タスク詳細（サブタスク・コメント込み） |
| `search_tasks` | 読み取り | ローカルストアの全文検索 |
| `list_projects` | 読み取り | プロジェクト / セクション一覧 |
| `create_task` | 書き込み | タスク作成 |
| `update_task` | 書き込み | 完了切替・期日・担当者などの更新 |
| `add_comment` | 書き込み | コメント追加 |
| `sync` | 操作 | 同期の実行と状態確認 |

- 読み取りはローカルストアから返すため、高速でオフラインでも動作する。
- 書き込みは TUI と同じ送信待ちキューを通す。
- `--read-only` オプションで書き込みツールを無効化できるようにする。

> 参考: Asana 公式の MCP サーバーも存在する。本ツールは「ローカルキャッシュによる高速・オフライン動作」と「TUI と同じデータを共有できる」点で差別化する。

## 8. オフライン・同期

- **ローカルストア**: SQLite（`~/.local/share/asana-tui/store.db`）。タスク・プロジェクト・セクション・ユーザー・タグ・コメントを保存。全文検索に SQLite FTS5 を使う。
- **初回同期**: ワークスペース・自分の担当タスク・参加プロジェクトのタスクを取得。
- **差分同期**:
  - タスク: `GET /tasks?project=...&modified_since=...` や `GET /tasks?assignee=me&workspace=...&modified_since=...` で変更分だけ取得。
  - 必要に応じて Events API（`GET /events?resource=...&sync=...`）を使う。同期トークンは期限が切れるので、切れたら全件取得し直す。
  - 起動時と一定間隔（デフォルト 5 分）、および手動（`r`）で実行。
- **オフライン編集**: 操作をローカルに即時反映し、送信待ちキューに保存。オンライン復帰時に順番に送信する。
  - オフラインで作成したタスクには仮 ID を振り、送信成功後に本物の gid に置き換える。
- **競合の扱い**: 送信前にサーバーの `modified_at` を確認する。ローカルの元データより新しく、かつ同じ項目が変更されていれば競合として扱い、ユーザーに選ばせる。別の項目の変更ならそのまま送る（後勝ち）。
- **レート制限**: 429 のときは Retry-After に従ってリトライ。`opt_fields` で取得する項目を最小限にする。

## 9. 認証（OAuth 2.0）

- 開発者（自分）が Asana の開発者コンソールでアプリを登録し、client ID を取得する。
- `asana-tui auth login` の流れ:
  1. ローカルでコールバック用の HTTP サーバーを起動（`http://localhost:<port>/callback`）
  2. ブラウザで Asana の認可画面を開く（PKCE を使う）
  3. 受け取った認可コードをアクセストークン / リフレッシュトークンに交換
- アクセストークンは約 1 時間で期限切れになるため、リフレッシュトークンで自動更新する。
- トークンの保存先は設定 `auth.token_store` で選ぶ:

| 値 | 保存先 | 備考 |
|----|--------|------|
| `keychain`（デフォルト） | macOS: Keychain、Linux: Secret Service | |
| `1password` | 1Password（`op` CLI 経由） | 保管庫とアイテム名は設定で指定（デフォルト: `Private` / `asana-tui`）。1Password デスクトップアプリと CLI の連携を有効にしておく必要がある |
| `file` | `~/.config/asana-tui/token.json`（権限 600） | キーチェーンも 1Password も使えない環境向け |

- 1Password の場合:
  - リフレッシュトークン（と、必要なら client secret）をアイテムのフィールドとして保存する。書き込むのはログイン時だけ。
  - アクセストークンは保存せず、起動時にリフレッシュトークンから取得してメモリ上に持つ。そのため 1 時間ごとの更新で 1Password に書き込むことはない。
  - 起動時に `op read` を呼ぶため、1Password がロックされていれば Touch ID などで解除を求められる。
  - `asana-tui auth migrate --to 1password` で保存先を移せるようにする。
- ブラウザがない環境（SSH 先の Linux など）では、認可 URL を表示し、ユーザーが手元のブラウザで開ける方式も用意する。
- `[要確認]` 配布バイナリに client secret を含める必要があるか。PKCE だけでトークン交換できるかを実装前に確認する。
- 予備手段として、環境変数 `ASANA_TOKEN` に Personal Access Token が設定されていればそれを優先して使う（開発用・ヘッドレス用）。`op run` と組み合わせれば 1Password から渡すこともできる。

## 10. 非機能要件

- **性能**: 起動から My Tasks 表示まで 0.5 秒以内（ローカルストアから表示し、同期は裏で行う）。
- **無料プランで動くこと**: 有料プラン限定の API・項目は使わない。
- **セキュリティ**: トークンはログに出さない。ローカルストアの権限は 600。
- **対応環境**: macOS / Linux のみ。
- **配布**: シングルバイナリ（goreleaser）、Homebrew tap。

## 11. 技術選定

| 項目 | 採用 | 理由 |
|------|------|------|
| 言語 | Go | シングルバイナリ配布が容易 |
| TUI | Bubble Tea + Lip Gloss + Bubbles | Elm アーキテクチャで状態管理しやすい |
| CLI | cobra | サブコマンド構成の定番 |
| ローカルストア | SQLite（modernc.org/sqlite） | pure Go で cgo 不要、クロスコンパイルが楽。FTS5 で全文検索 |
| MCP | 公式 Go SDK（modelcontextprotocol/go-sdk） | stdio サーバーを簡単に実装できる |
| OAuth | golang.org/x/oauth2 | PKCE・トークン自動更新に対応 |
| トークン保存 | zalando/go-keyring / 1Password CLI（`op`） | Keychain・Secret Service・1Password を同じインターフェースで切り替える |
| API クライアント | 自前の薄いラッパー（net/http） | 公式 Go SDK がないため、必要なエンドポイントのみ実装 |
| 設定 | `~/.config/asana-tui/config.toml` | XDG 準拠 |

## 12. 使用する Asana API

- `GET /users/me`
- `GET /workspaces`
- `GET /users/me/user_task_list?workspace=` → `GET /user_task_lists/{gid}/tasks`
- `GET /tasks?assignee=&workspace=&modified_since=` / `GET /tasks?project=&modified_since=`
- `GET /projects?workspace=`
- `GET /projects/{gid}/sections`, `GET /sections/{gid}/tasks`
- `GET /tasks/{gid}`, `GET /tasks/{gid}/subtasks`, `GET /tasks/{gid}/stories`
- `GET /events?resource=&sync=`
- `PUT /tasks/{gid}`
- `POST /tasks`
- `POST /tasks/{gid}/stories`
- v0.2 で追加: `/attachments`, `/tags`, `/tasks/{gid}/addFollowers`, `/status_updates`, `/teams`, `/tasks/{gid}/duplicate`, `/tasks/{gid}/addProject`, `/sections/{gid}/addTask` など
- OAuth: `https://app.asana.com/-/oauth_authorize`, `https://app.asana.com/-/oauth_token`
