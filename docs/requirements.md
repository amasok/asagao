# asana-tui 要件定義（ドラフト v0.2）

> ステータス: ドラフト v0.2。`[要確認]` の項目は未決定。決まり次第更新する。

## 1. 背景・目的

- ブラウザ / デスクトップアプリを開かずに、ターミナルから Asana のタスクを素早く確認・操作したい。
- キーボードだけで完結する操作体系により、日々のタスク処理（確認・完了・作成・コメント）の速度を上げる。

## 2. 想定ユーザー

- 主に開発者本人（ターミナル中心で作業するエンジニア）。
- 将来的には OSS として同様のニーズを持つ人にも配布可能にする `[要確認]`。

## 3. スコープ

### 3.1 MVP（v0.1）

| # | 機能 | 内容 |
|---|------|------|
| F1 | 認証 | Personal Access Token (PAT) を環境変数 or 設定ファイルから読み込む |
| F2 | ワークスペース選択 | 所属ワークスペース一覧を表示・切替 |
| F3 | My Tasks 表示 | 自分にアサインされた未完了タスクを一覧表示（期日順） |
| F4 | プロジェクト一覧 / タスク一覧 | プロジェクトを選択し、セクションごとにタスクを表示 |
| F5 | タスク詳細 | 名前・説明・担当者・期日・タグ・サブタスク・コメントを表示 |
| F6 | タスク完了 / 未完了切替 | 1 キーでトグル |
| F7 | タスク作成 | タイトル（＋任意で期日・担当者）を入力して作成 |
| F8 | コメント追加 | タスクにコメントを投稿 |
| F9 | ブラウザで開く | 選択中タスクを Asana Web で開く |
| F10 | 検索 / フィルタ | 表示中の一覧をタスク名でインクリメンタル検索。担当者・期日・タグ・完了状態で絞り込み。ワークスペース全体検索は Premium 以上で利用可能（8 章参照） |

### 3.2 v0.2 以降の候補

- タスク編集（名前・説明・期日・担当者・セクション移動）
- サブタスクの作成・完了
- インボックス（通知）表示
- オフラインキャッシュと高速起動
- 複数アカウント対応 / OAuth 認証
- カスタムフィールド表示
- テーマ・キーバインドのカスタマイズ

### 3.3 スコープ外

- ポートフォリオ / ゴール / レポート機能
- ファイル添付のアップロード
- Asana 管理者向け機能

## 4. 画面構成（案）

```
┌ Workspace: xxx ───────────────────────────────────────────┐
│ [Sidebar]          │ [Task List]            │ [Detail]     │
│  ▸ My Tasks        │ ☐ タスクA   11/15      │ タスクA       │
│  ▸ Inbox (v0.2)    │ ☐ タスクB   11/20      │ 担当: me     │
│  Projects          │ ☑ タスクC              │ 期日: 11/15  │
│   ・Project 1      │ ── Section 2 ──        │ 説明...       │
│   ・Project 2      │ ☐ タスクD              │ コメント...   │
├────────────────────────────────────────────────────────────┤
│ j/k:移動 enter:開く x:完了 a:追加 c:コメント o:ブラウザ ?:help │
└────────────────────────────────────────────────────────────┘
```

- 3 ペイン構成。端末幅が狭い場合は 1 ペインずつ遷移する。

## 5. キーバインド（案）

| キー | 動作 |
|------|------|
| `j` / `k` | 下 / 上へ移動 |
| `h` / `l` / `Tab` | ペイン移動 |
| `Enter` | 選択 / 詳細を開く |
| `x` | 完了トグル |
| `a` | タスク追加 |
| `c` | コメント追加 |
| `o` | ブラウザで開く |
| `r` | 再読み込み |
| `/` | 検索 |
| `f` | フィルタ |
| `?` | ヘルプ |
| `q` | 戻る / 終了 |

## 6. 非機能要件

- **性能**: 起動から My Tasks 表示まで 2 秒以内（キャッシュ導入後は 0.5 秒以内を目標）。
- **API 制限**: Asana API のレート制限（429）を考慮し、リトライ（Retry-After 準拠）と必要最小限のフィールド取得（`opt_fields`）を行う。
- **セキュリティ**: トークンはログに出さない。設定ファイルはパーミッション 600 を推奨。OS キーチェーン対応は v0.2 で検討。
- **対応環境**: macOS / Linux のみ。Windows はサポート対象外。
- **配布**: シングルバイナリ、Homebrew tap で配布 `[要確認]`。

## 7. 技術選定（案）

| 項目 | 推奨 | 代替 | 理由 |
|------|------|------|------|
| 言語 | Go | Rust | シングルバイナリ配布が容易、TUI エコシステムが成熟 |
| TUI | Bubble Tea + Lip Gloss + Bubbles | ratatui (Rust) | Elm アーキテクチャで状態管理しやすい |
| API クライアント | 自前の薄いラッパー（net/http） | — | 公式 Go SDK がないため、必要エンドポイントのみ実装 |
| 設定 | `~/.config/asana-tui/config.toml` | — | XDG 準拠 |

→ **決定: Go + Bubble Tea**

## 8. 使用する Asana API（MVP）

- `GET /users/me`
- `GET /workspaces`
- `GET /users/me/user_task_list?workspace=` → `GET /user_task_lists/{gid}/tasks`
- `GET /projects?workspace=`
- `GET /projects/{gid}/sections`, `GET /sections/{gid}/tasks`
- `GET /tasks/{gid}`, `GET /tasks/{gid}/subtasks`, `GET /tasks/{gid}/stories`
- `PUT /tasks/{gid}`（完了切替）
- `POST /tasks`
- `POST /tasks/{gid}/stories`（コメント）
- `GET /workspaces/{gid}/tasks/search`（ワークスペース全体検索。**Premium 以上のプランのみ**。Free プランでは取得済みタスクをクライアント側で絞り込む）

## 9. 決定事項・未決事項

### 決定事項

| 項目 | 決定内容 |
|------|----------|
| 言語 / TUI | Go + Bubble Tea |
| リポジトリ | private のまま |
| 対応 OS | macOS / Linux のみ |
| 検索 / フィルタ | MVP に入れる（F10） |

### 未決事項

1. MVP の認証方式（推奨: PAT のみ。下表参照）

| 方式 | 概要 | 長所 | 短所 |
|------|------|------|------|
| Personal Access Token (PAT) | Asana の開発者コンソールでユーザーが自分で発行 | 実装が最も簡単。アプリ登録が不要 | ユーザーが手動で発行して設定する必要がある |
| OAuth 2.0 | ブラウザでログイン → localhost にリダイレクトしてトークンを受け取る | 他の人に配布するときの体験が良い。リフレッシュトークンで更新できる | Asana へのアプリ登録、ローカルのコールバックサーバー、トークン更新処理が必要 |
| Service Account | Enterprise 向けの組織全体用トークン | 自動化に向く | 個人の TUI には不向き。Enterprise プラン限定 |
