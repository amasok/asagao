# クイック追加の文法 (Issue #5)

振る舞いを変える変更。

## なぜ

タスクを作るとき、担当・期日・タグを 1 行で書けるようにする: `牛乳を買う @hanako 明日 #買い物`。今の TUI の作成は `due:<期日>` しか読まず、担当やタグはあとで詳細から変える必要がある。

## 何を変えるか

- 1 行の入力の **末尾から** 語を読み、`@名前` (担当)、`#名前` (既存のタグ)、期日 (`dates.Parse` の形、または `due:<期日>`) を取り出す。名前として扱う語にぶつかったら止めるので、名前の途中の語 (「明日の準備」「#12 の件」) は読まない。最初の語はいつも名前。
- `@me` は自分。ほかはキャッシュのユーザーの名前 (空白を除いた全体、または空白で区切った 1 語) かメールの `@` より前に、大文字小文字を区別せず一致するもの。一致がなければ前方一致。どちらも 1 人に絞れたときだけ採用する。
- `#名前` は既存のタグの名前に一致するもの (大文字小文字・空白は区別しない)。1 つに絞れたときだけ採用し、新しいタグは作らない。
- 読めないトークン (一致なし・複数一致・2 つ目の担当や期日・`due:` のあとが日付でない) が来たら、そこで止め、それより前は名前に残す。何を読んだかと、読めなかったトークンとその理由を、TUI はステータス行、CLI は出力に出す。ユーザー名とタグ名は termsafe を通す。
- `\@` と `\#` で記号をそのまま名前に入れる。
- TUI: タスクの作成 (`a`) とサブタスクの作成 (`S`) で、いつも有効。
- CLI: `task create --quick` のときだけ有効 (今の挙動は変えない)。`--due` / `--assignee` と同じものを名前でも指定したらエラーにして、何も積まない。`--json` では読んだものを `quick` に入れる。
- 書き込みは今までどおり outbox を通す (タグは作成のあとに `add_tag` を積む)。マイグレーションはない。

## やらないこと

- MCP の `create_task` は変えない (構造化した引数がある)。
- 新しいタグは作らない。
- 名前の途中の `due:` は、もう読まない (末尾のものだけ)。
- 曜日 (「金曜」) や「来週」などの新しい期日の形は足さない。
